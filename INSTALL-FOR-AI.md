# Задание для ИИ. Установи DSH PTC Presets на Windows

Установи в DeepSeek Harness Desktop то, что попросил пользователь. Если он попросил весь комплект или передал эту инструкцию без уточнений, установи **54 пресета, все 10 связок субагентов и Research Manager**. Выполни шаги сам через терминал и доступные инструменты рабочего стола. После установки проверь новую сессию DSH.

Используй [DSH PTC Presets на GitHub](https://github.com/Kotpes537/dsh-ptc-presets). Для всех модельных пресетов используется один базовый установщик. Названия Astra, Fable, Qwen и других пресетов обозначают наборы инструкций. Они могут работать на одной модели, уже подключённой в DSH.

## Подготовь машину

1. Проверь, что доступны DSH Desktop, Git, Python 3.10+ и PowerShell 7. Установка проверена на DSH Desktop 0.2.2-rc.5. Если команды `python` нет, попробуй `py -3`. Если DSH ещё не создал профиль, запусти приложение один раз. Если не хватает компонента, сначала проверь доступные варианты на машине.
2. Возьми актуальную ветку `main` в отдельный каталог. Если у тебя уже есть чистая актуальная копия, используй её. Выполняй команды из корня репозитория. Запиши SHA коммита для отчёта.
3. Найди фактический профиль DSH Desktop. Для стандартной установки это `%USERPROFILE%\.dsh\profiles\desktop`. При заданном `DSH_HOME` проверь `profiles\desktop` в нём. Используй один и тот же фактический путь для базы и Research Manager.

```powershell
git clone --depth 1 --branch main https://github.com/Kotpes537/dsh-ptc-presets.git dsh-ptc-presets
if ($LASTEXITCODE -ne 0) { throw 'Git clone failed' }
Set-Location -LiteralPath .\dsh-ptc-presets
git rev-parse HEAD
$dshRoot = if ($env:DSH_HOME) { $env:DSH_HOME } else { Join-Path $env:USERPROFILE '.dsh' }
$profileDir = Join-Path $dshRoot 'profiles/desktop'
```

Сверь `$profileDir` с фактическим путём. Основной пакет можно собрать до выхода из DSH. Перед записью в профиль дождись завершения задач и выйди через меню приложения. Если существует `cordis.patch.yml`, сохрани отдельную копию перед установкой и запиши её путь.

## Установи пресеты и связки

Выбери параметры сборки по задаче пользователя.

| Запрос | Параметры после `build` |
| --- | --- |
| Весь комплект | `--team all`, затем установить Research Manager |
| Все базовые пресеты | Без параметров выбора |
| Отдельные модельные пресеты | Повтори `--preset <ID>` для каждого. [ID пресетов](presets/catalog.json) |
| Отдельная связка | `--only --team <имя>`. [Имена связок](presets/teams.json) |
| Только Research Manager | `--only --team research`, затем установить Research Manager |

При выборочной установке имеющиеся пресеты и допуски помощников сохраняются. Для Astra вместе с Research Manager используй `--preset ptc-astra --team research` и затем установи дополнение.

В блоке ниже показан полный комплект. Подставь параметры из таблицы для выбранного варианта.

```powershell
$ErrorActionPreference = 'Stop'
python -B -X utf8 .\scripts\presets.py build --team all
if ($LASTEXITCODE -ne 0) { throw 'PTC build failed' }
Expand-Archive -LiteralPath .\dist\DSH-PTC-portable.zip -DestinationPath .\dist\install-all
.\dist\install-all\Install-DSH-PTC.ps1 -ProfileDir $profileDir -WhatIf
```

Сборка проверяет контрольные суммы закреплённых материалов. Если папка распаковки уже занята другой сборкой, используй новую папку и тот же новый путь в командах установки. После успешного предпросмотра, при закрытом DSH, выполни запись.

```powershell
.\dist\install-all\Install-DSH-PTC.ps1 -ProfileDir $profileDir
```

Если предпросмотр показывает конфликт, выясни, расходятся ли файлы, декларации или только список помощников. Установщик умеет обновлять список в переносимом блоке при совпадении его остальных настроек. При конфликте с локальными изменениями сохрани исходные файлы и не заменяй весь профиль. Для известной старой версии `high-max.mjs` проверь точное совпадение с предыдущим публичным исходником и наличие резервной копии перед точечным обновлением. Неподтверждённые изменения оставь на месте и укажи, какая часть установки заблокирована.

## Добавь Research Manager

Выполняй этот шаг для полного комплекта или по запросу на Research Manager. Используй тот же Git-коммит и профиль.

```powershell
python -B -X utf8 .\addons\research-manager\install.py --profile-dir $profileDir
if ($LASTEXITCODE -ne 0) { throw 'Research Manager preview failed' }
python -B -X utf8 .\addons\research-manager\install.py --profile-dir $profileDir --apply
if ($LASTEXITCODE -ne 0) { throw 'Research Manager install failed' }
python -B -X utf8 .\addons\research-manager\install.py --profile-dir $profileDir
if ($LASTEXITCODE -ne 0) { throw 'Research Manager verification failed' }
```

Повторный предпросмотр должен показать ноль новых файлов и отсутствие нового пресета на добавление. Установщик проверяет версию модуля High и наличие нужных помощников. Для отдельной установки дополнения используй [задание для Research Manager](addons/research-manager/INSTALL-FOR-AI.md).

## Проверь результат в DSH

1. Открой DSH и создай **новую** сессию. Проверь выбранные пресеты и Research Manager, если он входил в задачу. Сверь ожидаемые идентификаторы с `presets` в `manifest.json` из пакета, а разрешённых помощников с выбранными связками из `presets/teams.json`.
2. Для полного комплекта проверь маршрутизацию на подключённой модели. В новой сессии **Astra** на Max используй [синтетический тест Qwen и GLM](docs/single-model.md#проверка-после-установки). Проверь два фактических вызова и итог **20%, 15%, +5 п.п.** Дочерние вызовы наследуют модель, когда в них не указаны `provider`, `model` и `reasoning_effort`.
3. В **Research Manager** на High запусти [пробный парный тест](addons/research-manager/INSTALL-FOR-AI.md#установи-дополнение-и-проверь). Проверь вызов GLM и вывод, что одного `p = 0,18` недостаточно для подтверждения эквивалентности. Для частичной установки запускай только тесты доступных ролей.
4. Если интерфейс или модель недоступны, проверь состав профиля на диске и перечисли, какие проверки в приложении остались открыты.

Сообщи, что установилось и что появилось в новой сессии. Укажи SHA коммита, профиль, путь к резервной копии и результат пробных запусков. При конфликте назови точный файл или блок.

## Откат

Сначала закрой DSH штатно. Если после установки профиль не правили, используй копию `cordis.patch.yml`, сделанную перед этой установкой. Если появились другие изменения, сверяй конфигурацию с копией и удаляй только добавленные блоки `DSH RESEARCH MANAGER` и `PORTABLE DSH PTC` либо восстанавливай прежний список связок. После отката открой новую сессию и проверь меню.
