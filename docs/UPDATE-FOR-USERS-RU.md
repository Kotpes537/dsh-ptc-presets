# Обновление модельных пресетов DSH

Инструкция для пользователей модельных пресетов DSH PTC Presets на Windows. Её можно целиком передать ИИ с доступом к этой машине и терминалу.

## Что происходит с обновлениями

1. GitHub Actions проверяет исходный архив промптов по понедельникам в 07:00 UTC, это 10:00 по Москве. GitHub может запустить задачу позже назначенного времени. [Отчёты мониторинга](https://github.com/Kotpes537/dsh-ptc-presets/actions/workflows/upstream.yml)
2. Сопровождающий проекта оценивает изменения, совместимость с DSH и результаты проверок. Отчёт об изменении источника сам по себе не означает, что в DSH PTC Presets уже вышло обновление.
3. После публикации изменений в нашем репозитории пользователь может поручить своему ИИ проверить установленный комплект и обновить его. Описание опубликованных изменений смотри в [журнале](../CHANGELOG.md) и истории репозитория. Перед обновлением ИИ должен назвать конкретный коммит или выпуск и изменения, которые он нашёл.

Мониторинг выполняется на GitHub и не зависит от включения компьютера пользователя. Он не устанавливает обновления на клиентские машины. Автоматическая проверка при выборе пресета или включении ПК для пользователей этого репозитория пока не поставляется. Установщик не ведёт полноценный журнал установленных версий и останавливается при отличающемся файле плагина.

Модельный пресет содержит инструкции и настройки DSH. Версия и доступность фактической API-модели зависят от выбранного провайдера.

## Что делать пользователю

Передай ИИ ссылку на эту страницу и поручение:

> Проверь обновления моих установленных модельных пресетов из https://github.com/Kotpes537/dsh-ptc-presets. Определи, что установлено на моём компьютере, сравни с последней опубликованной версией проекта и объясни, что изменилось для меня. При наличии совместимого обновления установи его, сохрани мои настройки и проверь результат в новой сессии DSH. Если найдёшь изменённые мной файлы или не сможешь надёжно определить их происхождение, покажи конкретный конфликт и останови замену этих файлов.

Для проверки ИИ нужен доступ к файлам профиля, терминалу и GitHub. При наличии доступной модели и интерфейса он сможет выполнить пробный запрос. Если проверка доступна только по файлам, он должен так и сообщить.

Если ИИ работает в том же DSH Desktop, который требуется закрыть для установки, он может проверить версии и подготовить резервную копию. Продолжение после закрытия приложения этой инструкцией не обеспечено. Для установки и проверки после перезапуска передай подготовленный результат отдельному агенту вне закрываемого DSH. Не считай обновление завершённым до проверки запущенного приложения.

## Порядок для ИИ

1. Определи установленный DSH Desktop, его версию и фактический профиль. По умолчанию это `%USERPROFILE%\.dsh\profiles\desktop`, при заданном `DSH_HOME` — `<DSH_HOME>\profiles\desktop`. Выясни установленные ID пресетов и связки из `cordis.patch.yml`. Учитывай дополнительные блоки и рабочие пресеты, если они есть.
2. Сравни текущий публичный коммит проекта, его журнал изменений и исходники с установленными файлами. Найди предыдущий опубликованный коммит, которому фактически соответствуют файлы, если это возможно. Наличие новой записи в отчёте мониторинга ещё не подтверждает наличие проверенного обновления нашего комплекта. Если изменений для установленного набора нет, сообщи об этом и заверши работу.
3. До записи дождись завершения активных задач DSH. Сохрани копии `cordis.patch.yml` и затрагиваемых файлов в отдельном каталоге с датой. Зафиксируй ID пресетов, разрешённых помощников и хеши до изменения. Если выполняешь эту задачу из закрываемого DSH Desktop, передай установку и последующую проверку агенту вне приложения. Внешний агент штатно закрывает DSH перед записью. Личные настройки и дополнительные блоки пользователя сохраняются.
4. Возьми проект по конкретному проверенному публичному коммиту. Собери пакет для установленных пресетов и нужных связок по [инструкции установки](../INSTALL-FOR-AI.md). Помни, что пакетные файлы общие для нескольких пресетов: проверь зависимости каждого затрагиваемого файла.
5. Запусти установщик с `-WhatIf`. Он проверяет контрольные суммы и обнаруживает конфликтующие файлы. Для точечного обновления существующего файла сначала сравни его байты с известной предыдущей опубликованной версией и с новой. Если файл соответствует прежней версии, сохрани копию и перенеси нужное изменение, затем повтори предпросмотр. Если происхождение или локальные правки неясны, не перезаписывай файл и сообщи точный путь и расхождение. Проверяй и общие зависимости.
6. Запусти установку, затем повторно проверь установленные ID и список помощников. Запусти DSH, создай новую сессию и проверь, что нужные пресеты отображаются. Если доступна модель, выполни небольшой тест через неё. Если проверка недоступна, сообщи об этом.
7. Сообщи исходную и новую версию, что реально обновлено, путь к копии, результаты проверок и оставшиеся конфликты. При неудаче сохрани описание состояния и восстанови изменённые файлы из копии, если это необходимо для возвращения профиля в рабочее состояние.

Если в профиле есть Research Manager, сохрани его файлы и блок конфигурации. Если обновляется общий модуль High или другая его зависимость, проверь совместимость дополнения и его разрешённых помощников отдельно. Эта инструкция не предусматривает безусловную замену Research Manager.

## Как откатить

Заверши задачи и закрой DSH. Сверь сохранённые до обновления файлы с текущими и восстанови затронутые файлы из резервной копии. Если после обновления появились другие важные правки, перенеси их в сохранённую конфигурацию. Открой DSH и проверь пресеты в новой сессии. Сохраняй резервную копию до проверки.
