# DSH PTC Presets

54 пресета для DeepSeek Harness Desktop. В комплекте адаптированные инструкции, архивные варианты Full, правила делегирования и навыки для продолжения длинных задач и проверки результата. Модель, провайдер и режим рассуждения выбираются отдельно в DSH.

## Установка на Windows

[Задание для ИИ. Установить все пресеты, 10 связок и Research Manager](INSTALL-FOR-AI.md)

Проверенная версия DSH Desktop — **0.2.2-rc.5**. Для сборки нужен Python 3.10 или новее, для установки — PowerShell 7. Запусти DSH хотя бы один раз, чтобы создать профиль. Команды сборки выполняются из корня репозитория.

```powershell
git clone https://github.com/Kotpes537/dsh-ptc-presets.git
Set-Location dsh-ptc-presets
```

### Модельные пресеты

Передай `--preset` для каждого нужного пресета. Используй его название в меню DSH. Список названий покажет команда `python scripts/presets.py list`.

```powershell
python scripts/presets.py build --preset Astra --preset "Claude Sonnet 5.5"
```

Пакет добавит выбранные пресеты и общие зависимости. Выборочная установка сохраняет уже установленные пресеты и допуски помощников. Сборка без `--preset` и `--only` включает все 54 пресета, в том числе Workflow и «Ревью».

### Рабочие пресеты и связки

[Каталог рабочих пресетов](addons/README.md)

- [Research Manager](addons/research-manager/INSTALL-FOR-AI.md) устанавливается отдельно. Его базу можно собрать командой `python scripts/presets.py build --only --team research`.
- Для отдельной агентской связки используй `--only --team <имя>`. Сборщик добавит ведущего, участников связки и общие зависимости. [Десять схем на выбор](docs/agent-schemes.md)

### Как поставить собранный пакет

```powershell
Expand-Archive .\dist\DSH-PTC-portable.zip -DestinationPath .\dist\portable -Force
```

Выйди из DSH через меню приложения. Затем проверь и запусти установку:

```powershell
.\dist\portable\Install-DSH-PTC.ps1 -WhatIf
.\dist\portable\Install-DSH-PTC.ps1
```

Скрипт добавляет пресеты в профиль `desktop`. Можно указать отдельный каталог через `-ProfileDir`. Если у профиля уже есть `cordis.patch.yml`, скрипт сохраняет его копию рядом. При конфликте локальной настройки или файла он останавливается и показывает путь. Для существующей установки сначала сравни декларации по ID. После установки открой новую сессию и проверь меню пресетов.

Для отката закрой DSH и убери блок `PORTABLE DSH PTC` из `cordis.patch.yml`. Если после установки профиль не редактировался, можно восстановить прежний файл из сохранённой копии.

## Как устроены пресеты

### Короткие ID в карточках DSH

Карточки используют короткие ID, например `astra`, `fable-5-2` и `review`.
Для уже установленного комплекта закрой DSH и передай обновление агенту с этой инструкцией.

```powershell
python -B -X utf8 scripts/migrate_ids.py
python -B -X utf8 scripts/migrate_ids.py --apply
```

Первый запуск показывает число изменяемых файлов. Второй сохраняет копии в папке профиля и обновляет ID и ссылки в инструкциях помощников. Для другого профиля передай `--profile-dir`. После запуска DSH выбери пресет в новой сессии. При продолжении старой сессии с прежним ID выбери его новое название. Таблица соответствий хранится в `presets/legacy-ids.json`. Старые ID также принимаются командой сборки.

- **Адаптированные** используют инструменты DSH, общие правила длинных задач и короткие инструкции под модель.
- **Full** добавляют архивный текст из зафиксированного источника и слой совместимости DSH. В открытой сборке пресет **Astra** также использует закреплённый архив GPT-6.2 Astra. Отличие Astra от **GPT-6.2 Astra Full** сохраняется в обвязке DSH.
- **Ревью** проверяет файлы рабочей области в режиме чтения. В замечаниях к архитектуре показывает конкретные зависимости и объясняет, какая правка из-за них затронет несколько модулей. Доступен во всех связках.

Делегирование ограничено числом одновременно работающих потомков главного агента. По умолчанию High допускает **2**, Max — **3**. Для Fable 5.2, Opus 5.5 и GPT-6.2 Astra Max допускает **4**. Для Grok 4.7, Gemini 4 Neon и Gemini 4 Hydrogen переданный адаптером `xhigh` использует потолок Max.

На High для ревью достаточно одного помощника, если он закрывает главный риск. При двух независимых вопросах, например вычислениях и допустимости вывода, помощникам дают разные поручения. Главный сверяет ответы с исходными данными и явно указывает границы вывода.

## Связки для субагентов

Выбери связку при сборке пакета:

```powershell
python scripts/presets.py build --team debug
```

Можно перечислить несколько связок, например `--team debug --team analysis`. Ключ `--team all` включает все допуски из таблицы.
Чтобы установить только участников выбранных связок и их зависимости, добавь `--only`. Флаги `--preset` и `--team` можно комбинировать.

| Связка | Главный пресет | Кого можно вызвать для отдельной работы |
| --- | --- | --- |
| `debug` | GPT-6.2 Astra | GLM-5.3 для диагностики, Ревью для проверки итогового diff |
| `delivery` | Claude Fable 5.2 Full | Gemini 4 Neon для разбора кода, Grok 4.7 для проверки сценария, Ревью |
| `analysis` | Kimi K3.1 Pro | Qwen 3.8 Max для сверки данных, Ревью для проверки выводов |
| `quick` | GPT-6.2 Sol | Claude Haiku 5.5 для поиска затронутого кода и выбора проверок |
| `migration` | Muse Spark 1.3 | Grok 4.7 для проверки инструкции на чистом профиле |
| `loyalty` | Kimi K3.1 Pro | Qwen 3.8 Max сверяет сегменты, активность, начисления и расчёты |
| `strategy` | Claude Fable 5.2 Full | Gemini 4 Neon собирает факты, GLM-5.3 проверяет допущения и экономику |
| `experiments` | GPT-6.2 Astra | Qwen 3.8 Max сверяет расчёты, GLM-5.3 проверяет контрольную группу, каннибализацию и альтернативные объяснения |
| `executive` | Claude Fable 5.2 Full | Kimi K3.1 Pro сверяет тезисы и цифры с источниками |
| `research` | Claude Fable 5.2 Full | Gemini 4 Neon собирает источники, Qwen 3.8 Max анализирует данные, GLM-5.3 проверяет методику и выводы |

Все связки поддерживают одну фактическую модель DSH. Дочерний агент получает выбранные инструкции и наследует маршрут модели родителя, когда в вызове не заданы другой провайдер и модель. Название пресета само по себе не выбирает API-модель.

Для маркетинговой задачи передай каждому агенту цель бизнеса, период, определения метрик, входные файлы и ожидаемый результат. Главный агент сводит выводы, проверяет источники и отделяет подтверждённые данные от гипотез. Ревью доступен в каждой связке для итоговой статической проверки.

Выбери главный пресет в новой сессии DSH. Для `debug` можно попросить агента: «Поручи диагностику субагенту с пресетом GLM-5.3. Передай ему файлы и критерий проверки. После правки передай итоговые изменения пресету Ревью».

Связка добавляет допустимых помощников при сборке. Главный агент сам подставляет ID выбранного пресета в вызов субагента. Модель и провайдер ребёнка выбираются по правилам маршрутизации DSH. [Конфигурация связок](presets/teams.json) · [Соответствие названий и ID для интеграций](presets/catalog.json)

Чтобы добавить связку к ранее установленному переносимому комплекту, собери ZIP с `--only --team` и повторно запусти установщик при закрытом DSH. В профиле с Research Manager установщик сохраняет прежние допуски. Для сброса связок в полном комплекте без Research Manager установи полную сборку без `--team`.

## Обновления источника

[Как пользователю обновить пресеты — простая инструкция](docs/КАК-ОБНОВИТЬ-ПРЕСЕТЫ.md)

[Как пользователям проверять и устанавливать обновления модельных пресетов](docs/UPDATE-FOR-USERS-RU.md)

Отчёт сравнивает текущий архив с последним проверенным коммитом. В нём видны изменения используемых файлов, новые возможные источники, переименования и прочие правки. На GitHub отчёт доступен в **Actions → Upstream prompts → Summary**. Можно запустить его вручную. Запланированная проверка идёт по понедельникам в 07:00 UTC (10:00 по Москве), время фактического запуска зависит от GitHub Actions. [Отчёты GitHub Actions](https://github.com/Kotpes537/dsh-ptc-presets/actions/workflows/upstream.yml)

Для локальной проверки:

```powershell
python scripts/presets.py upstream
```

Для выпуска новой версии сначала проверь отчёт и файлы источника. Затем обнови конкретные записи в `presets/upstream.lock.json`, пересобери ZIP и проверь установку. Отдельное поле `reviewed_commit` отмечает, до какого коммита просмотрен архив. Запланированная проверка публикует отчёт и оставляет выбор версий сопровождающему.

Архивные тексты скачиваются только при сборке локального ZIP. Для каждого файла зафиксированы коммит, путь, диапазоны строк и SHA‑256. В репозитории лежат декларации, адаптированные инструкции и ссылки на источники. [Описание источников](presets/local-plugins/ptc-workflow/full-prompts/SOURCES.md) · [Файл фиксации источников](presets/upstream.lock.json)

## Проверки перед изменением

```powershell
python scripts/presets.py check
python -m unittest discover -s tests -v
python scripts/presets.py build
```

Проверки сверяют каталог с декларациями DSH, реконструкцию архивных текстов по контрольным суммам и обработку переименований в исходном Git. GitHub Actions дополнительно устанавливает результат в отдельный профиль Windows.
