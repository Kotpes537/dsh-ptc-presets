# Проверка результата

1. Составь короткий список проверяемых требований. Для каждого выбери наблюдение, которое может обнаружить ошибку.
2. Проверь результат через обычную точку входа. Для кода запусти подходящие тесты после последней правки. Для данных сверь схему, итоговые значения и как минимум один дополнительный сценарий, если он нужен для оценки правил.
3. Для отчёта или документа открой исходник подходящим инструментом DSH. Используй MarkItDown для извлечения текста и таблиц из поддерживаемых локальных файлов, когда он доступен и разрешён для этих данных. Если важен внешний вид, дополнительно открой итоговый артефакт.
4. Если полезно независимое статическое ревью, передай ревьюеру ТЗ, входные данные или существующие пути и ожидаемый формат выводов. Проверь его выводы на финальной версии. Команды сборки и тестов выполняет главный агент.
5. Сообщи пользователю, что проверено, чем это подтверждено и где открыть результат. Укажи конкретную непроверенную часть, если она влияет на вывод.

## Проверка изменений перед передачей

При ревью изменений в репозитории сначала установи базовую версию. Если в проверку входят локальные изменения, включи их в охват. Подтверди каждое замечание по коду до передачи пользователю. Для исправленного замечания повтори проверку с теми же входами. После новых результатов CI или ревью продолжи с конкретного провалившегося шага и проверь итоговое состояние ветки.
