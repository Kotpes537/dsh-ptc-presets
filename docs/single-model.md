# Одна модель, несколько пресетов

Связки задают инструкции дочерних агентов. Все роли могут работать на единственной модели DeepSeek, подключённой в DSH.

## Установка полного набора

Установи DSH и выполни первый запуск. В DSH подключи свою модель штатным способом. Для сборки нужны Git и Python 3.10+, для установки PowerShell 7.

```powershell
git clone https://github.com/Kotpes537/dsh-ptc-presets.git
Set-Location dsh-ptc-presets
python scripts/presets.py build --team all
Expand-Archive dist/DSH-PTC-portable.zip -DestinationPath dist/portable -Force
```

Заверши работающие задачи и полностью выйди из DSH через меню приложения. Затем выполни:

```powershell
.\dist\portable\Install-DSH-PTC.ps1 -WhatIf
.\dist\portable\Install-DSH-PTC.ps1
```

Запусти DSH снова и открой новую сессию. Выбери главный пресет и свою модель DeepSeek. High или Max включает соответствующее дополнение по делегированию. Наличие модели Kimi, Claude или GPT для этих связок не требуется.

## Пример для CRM и лояльности

Выбери главный пресет Kimi K3.1 Pro или Astra. Добавь задачу и укажи абсолютные пути к данным, период, определения показателей и ожидаемый результат. Можно использовать такую формулировку:

> Работай на выбранной модели DSH. Запусти субагента через subagent с agent_preset=ptc-workflow-qwen-3-8-max для сверки сегментов, конверсий и расчёта эффекта акции. Передай ему все данные и определения. Не задавай другую модель или провайдера. После проверки собери выводы с периодом, знаменателем и ограничениями. При содержательном результате запроси итоговое статическое ревью через ptc-workflow-review.

## Пример для маркетинговой стратегии

Выбери Claude Fable 5.2 Full или Astra.

> Передай сбор фактов субагенту с agent_preset=ptc-workflow-gemini-4-neon. Передай проверку допущений субагенту с agent_preset=ptc-workflow-glm-5-3. Дай обоим цель бизнеса, рынок, период, исходные документы и критерии результата. Модель и провайдера наследуй от главного агента. Собери стратегию с источниками, гипотезами и способом проверки ожидаемого эффекта.

Для акций используй Qwen для расчётов и GLM для контрольной группы, каннибализации и альтернативных объяснений. Для презентации руководству передай сверку тезисов с исходниками пресету ptc-workflow-kimi-k3-1-pro.

## Проверка после установки

В новой сессии Astra отправь:

> Это синтетический тест связок без файлов и веба. Запусти двух субагентов через subagent. Первому задай agent_preset=ptc-workflow-qwen-3-8-max и передай данные: тест 100 человек, купили 20; контроль 100 человек, купили 15. Попроси посчитать конверсии и разницу в процентных пунктах. Второму задай agent_preset=ptc-workflow-glm-5-3 и передай те же данные. Попроси оценить обоснованность вывода об эффекте акции. Не указывай provider, model или reasoning_effort. Дождись обоих и сведи результаты.

Ожидаемые расчёты — 20%, 15% и разница 5 процентных пунктов. По таким данным эффект оценивается с существенной неопределённостью. В журнале проверь два вызова subagent, разные значения agent_preset и одинаковые фактические provider/model у главного и детей.

## Если установка уже есть

В переносимом блоке установщик может обновить список разрешённых пресетов и сохранить резервную копию, когда остальные настройки совпадают. При конфликте файлов или другого содержимого он укажет место расхождения.

При ручной установке найди tool-subagent с provider=spawn внутри Astra и общий блок wf_delegation. Перенеси из собранного шаблона две строки allowedAgentPresets. Для модели используется существующая маршрутизация. После правки перезапусти DSH и открой новую сессию.

Если agent_preset отсутствует в схеме инструмента, сначала проверь установленный список и перезапуск. Если запуск отклонён из-за потолка, дождись текущих детей. Если DSH сообщает Unknown agent preset, сверяй ID с presets/catalog.json.

Для отката связок установи пакет, собранный без --team. При ручных правках восстанови сохранённые строки. Главный агент сохраняет ответственность за объединение результатов и итоговую проверку.

## Подтверждённый контрольный прогон

26 ноября 2026 года в DSH Desktop 0.2.2-rc.5 выполнен приведённый выше тест. Главный агент использовал Astra, дети — Qwen 3.8 Max и GLM-5.3. У всех трёх в request/header зафиксированы provider=deepseek-official, model=deepseek-flash и reasoningEffort=max. Оба ребёнка завершили работу, главный агент получил результаты и закончил ход.

Главный агент независимо пересчитал доверительный интервал после ошибки одного ребёнка. Это подтверждает маршрутизацию разных пресетов на одну модель в этом сценарии. Качество иных задач требует отдельной проверки.
