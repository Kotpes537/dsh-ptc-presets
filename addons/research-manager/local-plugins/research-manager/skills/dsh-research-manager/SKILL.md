# Research Manager

1. Определи решение, владельца решения, целевую группу и вопрос. Уточни текущий этап и какой артефакт нужен. Прочитай актуальные правила проекта и только релевантные входы. Если источников не хватает, опиши, какие выводы доступны сейчас и что требуется для следующего шага.
2. Используй общий маршрут или явно выбранный рабочий контур организации либо клиента. Пороги, словари, версии баз и протоколы бери из актуальных источников проекта. Если пользователь предоставил свежие требования, сопоставь их с текущими файлами и назови значимые расхождения.
3. Открой нужный раздел [маршрутов](references/routes.md). Пройди запрошенный этап. Готовые проверенные входы можно использовать без повторения всей цепочки, сверив их версию и пригодность. Если профильный навык упомянут в архиве, используй его только при фактической доступности.
4. Для существенной методической работы дай GLM отдельную проверку до перехода к зависимому шагу. Qwen поручай воспроизводимый пересчёт, Gemini Neon — отдельный поиск разрешённых открытых источников. Запускай только нужных помощников. Укажи конкретные входы, границы доступа, критерии и формат ответа. Вызови `subagent` с нужным `agent_preset`; поля модели, провайдера и усилия оставь пустыми для наследования. По умолчанию один проверяющий этапа, второй только для другой существенной задачи.
5. Прогони три проверки по текущей версии: (а) бриф и полнота ответа, (б) числа и связь выводов с источниками, (в) слабые допущения, альтернативы и пригодность результата. Для простого ответа это короткая самопроверка без служебных файлов. По существенному этапу обозначь, кто проверил и что осталось. После изменения входов перепроверь зависимые результаты.
6. Выдай решение, основание, ограничение и следующий проверяемый шаг. При необходимости приложи таблицу «вопрос → вывод → источник/база → ограничение → действие». Для существенной передачи зафиксируй версию, проверяющего и вердикт. Согласование человека укажи отдельно, только если оно произошло.
