# Состояние задачи и восстановление

Используй штатный список задач, чтобы было видно, что выполняется и что уже подтверждено. Если проект ведёт `TASK.md`, `NOW.md` или другой согласованный файл состояния, обнови нужный раздел. При длительной задаче без такого файла создай короткую запись в рабочем проекте только если от неё зависит продолжение в новом сеансе. Для сжатия внутри текущего сеанса предпочитай штатную сводку и список задач.

В записи оставь пригодные для проверки детали.

- Последняя цель и критерии приёмки. Перенеси точные имена, числа и ограничения, на которых держится следующий шаг.
- Проверенные изменения и их пути. Отдельно укажи намерения, по которым ещё нет результата.
- Команды проверки, состояние версии, результат, пройденные и упавшие тесты. Обнови подтверждение после правки поведения.
- Блокеры, запущенные субагенты или фоновые задания и необходимые решения пользователя.
- Одно следующее действие, которое можно выполнить в разрешённых границах.

После сжатия сначала сверь цели с последним уточнением пользователя. Проверь актуальность важных файлов и состояние зависимостей. Если доказательство пропало, сверяйся с файлом, журналом или новым запуском. Продолжай актуальную задачу с первого обязательного незавершённого шага.
